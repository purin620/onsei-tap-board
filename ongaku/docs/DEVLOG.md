# 開発記録

## 2026-11-25　バージョン 1.0.0（最初の版）

依頼書「音楽スイッチ教材 開発依頼・引き継ぎ書」をもとに作成。第1段階を優先し、第2・第3段階も一通り作った。

### 作りの方針（技術メモ）

- **ビルド不要**のHTML・CSS・JavaScript（ES Modules）。GitHub Pages の `ongaku/` フォルダで配信する想定。
- **音の再生は Web Audio API**。曲を前もってデコードし（いまの曲・次の曲）、押した瞬間に `AudioBufferSourceNode` で鳴らす。<audio> 要素より遅延が小さく、部分再生・音量（iPadでは <audio> の音量が変えられない）にも対応できるため。
  - メモリに置くのは最大3曲分。5分の曲で約100MBになるので、これ以上増やさない。
  - 押す→すぐ離す（モードE）や、準備中に止められた場合の取り違えを、世代番号で防いでいる。
- **入力**（`js/input.js`）：
  - `keydown` の `repeat` と、押している最中の2回目の `keydown` は無視 → 長押しで連続入力にならない。
  - 画面ボタンは `pointerdown` で即反応。直後に来る `click` は無視（二重反応防止）。
  - `click` だけが届く入力（スイッチコントロールの項目選択、VoiceOver）は1回の入力として扱う。
  - 歯車は `aria-hidden` にして、スイッチコントロールのスキャン対象から外した。1.5秒長押しでのみ開く。
  - 「誤入力の防止」（受け付けない時間）は、有効な操作のあとだけ数える。
- **保存**：IndexedDB。音データは Blob ではなく ArrayBuffer で保存（過去にiPadで Blob の保存・再生に問題があったため。`f921f1a` の対応を参考）。`navigator.storage.persist()` を要求。
- **オフライン**：`sw.js`。保存したものをすぐ使い、裏で更新する方式（学校のWi-Fiが遅くても待たない）。
- **画面の消灯防止**：Screen Wake Lock API（対応している iPadOS のみ）。
- **消音モード**：`navigator.audioSession.type = 'playback'`（Safari 16.4 以降で対応、それ以前は無視される）。

### 気になっている点（実機で確認したい）

- iPadOS で、外部キーボードの `keydown` が音を鳴らすための「ユーザー操作」とみなされるか。だめな場合でも「学習スタート」で音声を有効にしているので鳴る見込みだが、長時間の放置後に止まる可能性がある。
- 長い曲をたくさん登録したときのデコード時間（曲を変えた直後に押すと、最初の1回だけ遅れる可能性）。
- ホーム画面のアプリでの CSV・バックアップの保存（`download` 属性）の動き。うまくいかなければ共有シート（`navigator.share`）に切り替える。
- Bluetoothスイッチインターフェースの機種ごとに届くキー。

## 今後の機能追加の候補

- 曲ごとの画像（ジャケット写真）をボタンに表示する（AACの選択肢につなげる）
- 2〜4曲から選ぶ「選択モード」（曲ごとにボタン／スキャン）
- 再生中の残り時間を、児童にも分かる形で表示する（点滅なし）
- 効果音（初期設定は無効）
- 入力を受け付けるまでの「ためし押し防止」（一定時間押し続けたら反応）
- 記録の週・月ごとのまとめ、個別の指導計画の様式に合わせた出力
- 共有シートでの CSV・バックアップの送り先選択
